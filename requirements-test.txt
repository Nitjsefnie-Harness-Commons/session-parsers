# Test-only toolchain, pinned so a tool release cannot turn CI red on an
# unchanged commit (same reason as requirements-dev.txt).
#
# The SUITE itself needs nothing: it is stdlib unittest driven by
# run_tests.py, and the package is stdlib-only on purpose. `coverage` is
# here for the gate in tests.yml, which also calls `--format=markdown` and
# `--fail-under` directly so the gate is a step of its own and the summary
# still renders when it is red.
#
# Coverage runs each suite as its own subprocess with --parallel-mode and
# then combines, because that is exactly what run_tests.py does. Running
# them in one process would not be measuring the thing CI actually runs.
#
# There is deliberately NO pytest here, and no speed.yml in this repo.
# pytest cannot run these suites: the tests are plain functions taking
# helper arguments, which pytest reads as fixture requests. Checked in
# every repo of this family — collection either errors outright or finds
# nothing at all. The speed comparator needs --junitxml, which only pytest
# emits, so there is no timing harness to build the gate on.
